## P1（4 项）

### P1-1 Esc 逻辑写反 ×2（Shell）
- `src/shell/canvas/ContextMenu.tsx:286-292` 与 `src/shell/tools/ToolRail.tsx:30-34`
- `if (event.key === 'Escape') return;` 应为 `!== 'Escape'`。现状：按任意键关闭面板/菜单并吞掉全局快捷键，按 Esc 反而关不掉；图库搜索框打一个字整个面板就关闭。
- 修复：1 行条件反转 ×2。

### P1-2 Canvas `apply()` 并发回滚丢数据（kernel）
- `src/kernel/canvas-host.ts:336-340`（previous 捕获于 309）
- 两个 apply 交错、第一个 persist 失败时，回滚把第二个的内存修改一并抹掉，但第二个仍返回成功（已脚本实证：B 报成功但其节点消失）。
- 修复：以写入队列单元为单位记录/回滚，或失败时以磁盘场景为回滚基准。

### P1-3 journal 伪造 → 任意文件删除（Rust）
- `src-tauri/src/vault/paths.rs:76-88`（is_reserved 大小写敏感精确比较）
- macOS 默认大小写不敏感 FS 上 `.Workbench/.Journal/` 变体绕过写入黑名单；journal 中 `temp` 字段经 `root.join()` 可为绝对路径，recover 时 `remove_file` 即任意文件删除；亦可覆写 `.lock` 制造双写者。
- 修复：darwin 大小写折叠比较 + 已存在前缀 canonicalize 校验（顺带修 P2-8 symlink 穿越面）。

## P3（约 40 项，摘要）

- **数据一致性**：`docs.read()` 带副作用（emit external + bump rev，契约 D6 边界）；软删除 trash 副本与原文档同 id（仅靠 Rust 排除 `.workbench/` 兜底）；契约 D4 的 `core.doc.purge` 不存在——回收站只进不出；重复 id 时 `byPath` 残留陈旧映射。
- **Shell**：拖拽手势无 pointerId 过滤 / 无 `onLostPointerCapture` 兜底 ×3；CanvasNodeView 编辑中外部更新清空草稿；AI「删除…」busy 期间可点覆盖进行中提案；inline-AI 撤销会静默吞掉中间人工编辑；图库缩略图用原图 data URL 不降采样、全库正文每次打开全量重扫；大列表无虚拟化（规模备忘）。
- **Rust**：密钥结构体派生 `Debug`（当前无打印点，属隐患）；流式取消在停滞时最长卡 90s；`list_models` 整包缓冲后才查大小；watcher 重命名拆成两条事件、指纹漏报窗口；孤儿 `.ember-tmp-` 临时文件永不清理；读路径无内存上限；journal 单行损坏 → 启动即 panic（用户无法自救）；锁 Drop 阻塞至多 5s；CSP `style-src 'unsafe-inline'`。
- **数据层**：ui.json 未来 schemaVersion 被静默降级覆写；frontmatter tags 缺 256 字符校验；canvas `label: ""` 未归一化为 null；merge3 上限 ~2000 行即拒绝合并；大小写折叠路径冲突静默 last-wins；`.gitignore` 未忽略 `.env*` 与 `.workbench/`；engines `>=22.12` 与 type-stripping 实际要求 `>=22.18` 不符；`flushMachineUiWrites` 注释承诺关闭前调用但无调用点；mutate/links 高风险分支无直接单测。
- **待验证**：frontmatter extra 的 `__proto__` 键可能静默丢失；pnpm `allowBuilds` 字段名是否被识别；katex 0.19 与 @types/katex 0.16 版本错配。

## 已确认干净的关键面

CSP 与 devtools 配置收敛、capability 最小权限；TS/Rust 双层路径穿越防护（除上述两处绕过面）；ULID、merge3 diff3 语义、canvas mutate 整批校验、invoke 命令名/参数逐一匹配；journal prepared→rename→committed 与 fsync 时机正确；命令层无 unwrap；zustand store 全部不可变更新；FloatEditor 会话生命周期与 StrictMode 双挂载防护正确。
